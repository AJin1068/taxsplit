# 가정 목록

개발(또는 기획)이 사람에게 묻지 않고 **추천안으로 정한 것**을 모으는 곳입니다. 규칙은 `CLAUDE.md` "작업 순서" 2번에 있습니다.

- **세법 해석**: 출처가 없거나 원문이 두 가지로 읽히는 경우입니다. 예를 들어 나이 요건을 못 채운 가족의 의료비를 공제하는지, 아무도 기본공제를 받지 않는 가족의 카드 사용액을 누구에게 넣는지 같은 것입니다.
- **개발 판단**: 구현 방식, 구조, 범위 안에서의 선택을 적습니다. 범위 경계(Issue "하지 않을 것"을 넘는 것)와 Issue·설계 문서에 없는 새 단계·화면도 여기에 적습니다. 이런 것은 "사람 확인: TODO"로 둡니다.

정답 데이터 값·채점 기준(`eval/`), 돈이 드는 외부 서비스·데이터 정책, 되돌리기 어려운 것은 여기에 적지 않습니다. 이 세 가지는 개발이 멈추고 사람에게 묻습니다.

이 목록은 README·화면에서 "이 데모는 이렇게 가정했다"로 보여 줄 자료가 됩니다.

## 쓰는 법

1. 한 줄에 하나씩 적습니다. 번호는 `A-001`부터 차례로 붙이고, 지운 번호는 다시 쓰지 않습니다.
2. **확신** 칸
   - 분명: 근거 문서가 직접 말한다.
   - 애매: 근거 문서가 직접 말하지 않거나 다른 안도 그럴듯하다. 범위 경계·새 단계·화면은 늘 "애매"로 적는다.
3. **사람 확인** 칸
   - "확신: 분명"이면 `-`로 둔다.
   - "확신: 애매"면 `TODO`로 두고, 사람이 보면 `확인함 YYYY-MM-DD`로 바꾼다.
   - TODO는 구현·PR·merge를 막지 않습니다. 사람은 시간이 날 때 TODO만 골라 봅니다. 다르게 정하면 새 Issue로 고칩니다.
4. **근거** 칸에는 문서 정식 이름과 인쇄 쪽·PDF 쪽을 씁니다. 예: 국세청 「2025년 원천징수의무자를 위한 연말정산 신고안내」 인쇄 389쪽, PDF 407쪽. 근거가 없으면 "출처 없음"이라고 씁니다.
5. 코드에는 그 규칙이나 선택 옆에 주석을 답니다.
   - 확신이 분명하면 `# 가정: docs/assumptions.md A-001`
   - 애매하면 `# TODO(사람 확인): docs/assumptions.md A-001`
6. 세법 숫자(공제율, 한도, 문턱)는 지어내지 않습니다. 출처가 전혀 없는 숫자는 코드에 `TODO(확인 필요)`로 남기고, 이 목록에도 한 줄을 적습니다.
7. PR 설명 "기록"의 "개발이 정한 것"에 이 목록의 항목 번호를 적습니다. "확인해 주세요"에 "누가 답하나: 사람"으로 올리지 않습니다. 원문 대조가 필요하면 "누가 답하나: 기획"으로 올립니다.
