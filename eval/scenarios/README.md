# 평가 시나리오

평가 하네스(PR 11)가 에이전트를 시험하는 데 쓰는 시나리오입니다. 시나리오 하나는 **가상 가구 하나와 가상 사용자가 아는 사실**이고, 기준 정답은 검증된 계산 엔진이 만듭니다(ADR-0004 정답 사슬).

- 이 폴더는 `eval/` 벽 안이라 개발 PR이 고칠 수 없습니다. 기획이 `eval/` 브랜치 PR로 만들고 사람이 검수합니다.
- 채점에는 `status: confirmed` 시나리오만 씁니다.
- 홀드아웃 시나리오는 이 레포에 두지 않습니다(같은 형식으로 레포 밖에 둠).
- 시나리오의 `id`와 부양가족 이름은 처리 코드·프롬프트에 넣으면 안 됩니다(답 외우기 검사가 찾음).

## 폴더

| 경로 | 내용 |
| --- | --- |
| `v0/` | v0 시나리오 10개 (`v0-01.json` ~ `v0-10.json`) |
| `make_gold.py` | 기준 정답(`gold`) 만드는 스크립트 |
| `test_make_gold.py` | 스크립트 테스트(같은 입력이면 같은 결과, confirmed 덮어쓰지 않음) |

## 칸

| 칸 | 뜻 |
| --- | --- |
| `id` | `v0-01` 같은 번호. 파일 이름과 같다 |
| `version` | 시나리오 묶음 버전(`v0`). 묶음을 바꾸면 버전을 올리고 기준 수치를 다시 잰다 |
| `status`, `review` | `draft` / `confirmed`, 검수한 사람과 날짜 |
| `title` | 사람이 읽는 한 줄 |
| `groups` | 덮는 공제 그룹: `dependent`(부양가족), `child`(자녀), `medical`(의료비), `education`(교육비), `card`(카드) |
| `spouse_names` | 부부 이름(가상). 가상 사용자와 간소화 자료가 쓴다 |
| `household` | 진짜 가구. 배분 비교 입력(`agent/src/taxsplit/allocation/models.py` `Household`) 모양 그대로, 기본값인 칸은 뺀다 |
| `documents` | 대화 시작 때 올리는 간소화 자료 2개(부부 각자). PR 12 추출 결과(`agent/src/taxsplit/extract/models.py` `ExtractedDoc`) 모양 |

| `persona` | 가상 사용자의 말투·성향 |
| `facts` | 가상 사용자가 아는 사실. `id`(`f1`…), `kind`, `text` |
| `gold` | 기준 정답. `make_gold.py`가 채운다(손으로 쓰지 않음) |

### `documents`에 넣는 것과 넣지 않는 것

간소화 자료에 실제로 나오는 것만 넣습니다(Issue #109 "꼭 물어야 할 정보" 표의 "왜 PDF로 알 수 없나").

- 넣음: 보험료(국민연금·건강·고용·노인장기요양), 의료비·교육비·카드 항목, 대상자 이름과 생년.
- 넣지 않음: 누가 냈나, 부양가족 소득, 장애 여부, 총급여.
- 부양가족 지출은 부부 중 한쪽(`documents`를 만든 쪽, 자료 제공에 동의받은 쪽으로 가정) 자료에 모두 나옵니다. 그래서 자료에 나온 쪽이 낸 사람이라는 뜻이 아닙니다.
- 지금은 모두 2025년 귀속 자료입니다(작년 자료로 시작하는 경우는 다음 버전 후보).

### `facts.kind`

| 값 | 뜻 | 채점 |
| --- | --- | --- |
| `must_ask` | 꼭 물어야 할 것. 답에 따라 결과가 바뀐다 | 누락 질문 비율은 이것만 센다 |
| `may_assume` | 짐작해도 되는 것. 문맥으로 알 수 있거나 틀려도 결과가 같다 | 물어도 묻지 않아도 감점 없음 |
| `background` | 물으면 답해 주는 그 밖의 사실 | 세지 않음 |

`must_ask`로 적은 사실은 모두 "모르고 짐작하면 기준 정답이 바뀌는 것"입니다(아래 표의 "짐작하면").

### `gold`

| 칸 | 뜻 |
| --- | --- |
| `plan_count` | 계산한 배분안 수 |
| `best_assignments` | 부부 결정세액 합계가 가장 작은 안 전부(부양가족 이름 → `husband`/`wife`) |
| `best_total` | 그 합계(원) |
| `plans` | 모든 배분안과 합계. 채점이 "에이전트가 고른 안"의 금액을 여기서 찾는다 |
| `headline_saving` | 흔한 방식 A·B 중 차이가 작은 쪽과 최적안의 차이(원) |
| `members` | 부양가족 이름·관계·출생연도. 채점이 에이전트의 가족과 짝지을 때 쓴다 |
| `engine` | 만든 엔진 커밋과 정답 사슬 문장 |

## 기준 정답 만들기

```bash
cd agent
uv run python ../eval/scenarios/make_gold.py --engine-commit $(git rev-parse --short HEAD)
uv run python ../eval/scenarios/make_gold.py --engine-commit $(git rev-parse --short HEAD) --check  # 바뀔 것만 보기
uv run python ../eval/scenarios/test_make_gold.py
```

- 같은 입력이면 파일이 글자 하나까지 같습니다(시각·난수 없음, 정렬 고정).
- `confirmed` 시나리오의 `gold`는 덮어쓰지 않습니다. 엔진을 고쳐 값이 달라지면 차이를 출력하고 1로 끝납니다. 사람이 다시 검수합니다.
