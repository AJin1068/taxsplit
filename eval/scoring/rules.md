# 채점 규칙 (v0)

평가 하네스가 에이전트 대화를 채점하는 규칙입니다. Issue #123(PR 11a)에서 정하고 사람이 승인했습니다. 바꾸려면 `eval/` 브랜치 PR로 고치고, 기준 수치(PR 15)를 다시 잽니다. 숫자의 뜻은 `docs/eval-plan.md` 3장 AI 대화 층을 따릅니다.

**대화 하나** = 시나리오 하나 × 반복 1번. 시나리오마다 기본 3번 돌립니다(AI 답이 매번 조금씩 달라서).

**채점에 쓰는 시나리오**: `status: confirmed`만. `draft`는 실행은 해도 점수에서 빼고 따로 적습니다.

## 숫자

### 1. 배분안 일치율

- 정의: 대화가 끝날 때 마지막으로 성공한 배분 비교에서 보여 준 최적안(부양가족 → 남편/아내)이 기준 정답의 최적안(`gold.best_assignments`) 중 하나와 **똑같은** 대화의 비율.
- 부양가족은 (관계, 출생연도)로 진짜 가족과 짝짓습니다. 에이전트가 붙인 이름은 보지 않습니다.
- 0으로 보는 경우: 배분 비교가 한 번도 성공하지 않음, 짝이 안 맞는 가족이 있음(출생연도가 틀림 등), 요건이 되는 가족을 빼먹음, 요건이 안 되는 가족을 넣음.

| 예 | 결과 |
| --- | --- |
| 진짜 "어머니(1950년생)"를 에이전트가 "어머님"으로 적고 같은 쪽에 넣음 | 맞음 |
| 최적안이 두 가지(같은 금액)인데 그중 하나를 고름 | 맞음 |
| 어머니 소득을 묻지 않고 0원으로 넣어 요건이 안 되는 어머니를 넣은 안을 고름 | 틀림 |
| 배분 비교 전에 "확인 필요"로 끝남 | 틀림 |

### 2. 놓친 금액 (참고)

- 정의: 에이전트가 고른 안을 진짜 가구에서 계산한 부부 결정세액 합계 − 기준 정답 최적 합계(원). 기준 정답 `plans`에서 찾습니다.
- 그 안이 `plans`에 없으면(요건이 안 되는 가족을 넣었거나 빼먹음) "알 수 없음".
- 4개 숫자에 넣지 않고 틀린 대화를 설명할 때 씁니다.

### 3. 누락 질문 비율

- 정의: 꼭 물어야 할 사실(`facts.kind = must_ask`) 중 가상 사용자가 대화 끝까지 알려 주지 않은 것의 수 / 전체 꼭 물어야 할 사실의 수(모든 대화를 합쳐서).
- "알려 줌"은 가상 사용자가 답마다 남긴 사실 id로 셉니다. 사용자가 묻기 전에 먼저 말해 준 것도 알려 준 것입니다.
- 짐작해도 되는 사실(`may_assume`)은 세지 않습니다. 물어도 감점하지 않습니다.
- v1: 꼭 물어야 할 사실에는 배분안은 그대로이고 부부 세금 합계(`gold.best_total`)만 바꾸는 것도 넣습니다(예: 난임시술비, 교복·체험학습비). 모르면 사용자가 환급을 덜 받기 때문입니다. v0의 꼭 물어야 할 사실은 모두 배분안을 바꾸는 것이라 이 줄로 달라지지 않습니다.

| 예 | 결과 |
| --- | --- |
| 꼭 물어야 할 사실 2개 중 1개만 물음 | 이 대화의 누락 1/2 |
| 아이 소득(짐작해도 되는 것)을 묻지 않음 | 감점 없음 |
| 사용자가 먼저 "어머니 소득 없어요"라고 말함 | 알려 줌으로 셈 |

### 4. 잘못된 인자 비율

- 정의: 도구 호출 중 인자 검사에 떨어진 호출(`invalid_args`) 수 / 전체 도구 호출 수(거절된 호출 포함, 모든 대화를 합쳐서).
- 도구를 한 번도 부르지 않은 대화는 분모에 들어가지 않습니다(배분안 일치율에서 0으로 잡힘).

### 5. 순서 위반 횟수

- 정의: 요건 확인 전에 배분 비교를 부르는 등 순서 규칙 위반(`order_violation`) 수의 합.

### 6. 대화당 비용

- 정의: 메인 에이전트 AI 호출 비용(USD)의 합 / 대화 수.
- 가상 사용자·GPT 채점 비용은 따로 적고 여기 넣지 않습니다. 비용을 모르는 호출이 있으면 "알 수 없음".

### 7. 빈 곳 알림 적중률 (v1부터)

- 정의: 시나리오의 내야 할 카드(`gaps_expected.show`) 중 대화 중에 실제로 낸 것의 수 / 내야 할 카드 수(모든 대화를 합쳐서).
- 카드는 항목 ID(`gap.*`)와 누구 일인지(관계·출생연도)로 맞춥니다. 정답의 `member`가 `null`이면 그 ID의 카드 아무거나 맞음입니다. 누구 일인지 모르는 카드(`member: null`)는 "그 가족" 정답에 맞히지 않습니다.
- `gaps_expected`가 없는 시나리오, 카드를 기록하지 않은 실행 기록(`gaps` 칸 없음)은 세지 않습니다. 하나도 없으면 "알 수 없음".

| 예 | 결과 |
| --- | --- |
| 동의 안 한 시어머니(1955년생)에게 동의 안내 카드를 냄 | 맞음 |
| 1956년생 가족에게 냄 | 틀림(다른 사람) |
| 늘 묻는 안경 질문을 냄 | 세지 않음(정답에 없음) |

### 8. 빈 곳 오알림 수 (v1부터)

- 정의: 내면 틀린 카드(`gaps_expected.not_show`)를 낸 수의 합. 놓칠 게 없는 가구(v1-05)의 0건이 기준입니다.
- 같은 ID라도 다른 가족의 카드는 오알림이 아닙니다(예: 2006년생 아들의 성년 안내는 맞고, 2012년생 딸에게 내면 오알림).

| 예 | 결과 |
| --- | --- |
| 자료가 이미 있는 친정어머니에게 "동의가 안 된 것 같아요" | 오알림 1 |
| 19세 미만 자녀에게 동의 안내 | 오알림 1 |
| 초등생에게 체험학습비 질문 | 세지 않음(맞는 질문) |

### 항목별 숫자 (v1부터)

빈 곳 숫자는 항목 ID마다 따로 냅니다(`by_gap`: 기대·적중·오알림 수). 평균 뒤에 망가진 항목이 숨지 않게 하려는 것입니다. 7·8은 아직 "기준 수치와 비교"의 떨어짐 판정에 넣지 않습니다(v1 기준 수치가 없음). 기준을 잰 뒤 넣을지 정합니다.

### 그룹별 숫자

시나리오의 `groups`(부양가족·자녀·의료비·교육비·카드)마다 위 숫자를 따로 냅니다. 평균 뒤에 망가진 그룹이 숨지 않게 하려는 것입니다.

### GPT 채점 (참고, 선택)

- 실행기에 `--judge`를 준 경우만. 채점 모델은 GPT(ADR-0006, 채점받는 Claude와 다른 회사).
- 묻는 것 하나: "최종 답의 설명이 배분 비교 결과(누가 누구를 공제받는지, 흔한 방식 대비 차이)와 맞는가?" 맞음/틀림과 이유.
- "설명 일치율(참고)"로 따로 적고 위 숫자에 섞지 않습니다.

## 기준 수치와 비교

지금 결과를 기준 결과(예: `eval/baseline-2026-11-22.json`, PR 15)와 비교합니다.

| 판정 | 조건 |
| --- | --- |
| 떨어짐 | 배분안 일치율이 10%p 이상 떨어짐, 또는 누락 질문 비율이 10%p 이상 오름, 또는 잘못된 인자 비율이 10%p 이상 오름 |
| 비용 늘어남 (경고) | 대화당 비용이 기준의 1.5배를 넘음. 떨어짐은 아님 |
| 같음 또는 좋아짐 | 그 밖 |

10%p는 v0 시나리오 10개에서 시나리오 1개가 바뀌는 정도입니다. 반복 3번 평균이라 한 번의 우연으로는 잘 넘지 않습니다.
