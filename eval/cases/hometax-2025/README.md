# 홈택스 모의계산 맞벌이 사례 2025 귀속 (PR 3c)

가상 맞벌이 가구를 홈택스 「연말정산 미리보기」 세액계산 화면에 넣어 얻은 **부부 각각의 결정세액과 중간값**을 사례 파일로 옮긴 것입니다. 국세청 「2025년 원천징수의무자를 위한 연말정산 신고안내」(2025.12 발간, 정오표 2026.02.03)(PR 3a, `../nts-2025/`)에는 맞벌이 사례가 없어서, 이 사례로 계산 엔진(PR 4·5) 검증을 보완합니다. 정답 사슬 1단계의 바깥 정답입니다(`docs/adr/0004-ground-truth-chain.md`).

- 실행: 2026-11-17, AJin1068이 직접 넣고 결과 화면을 캡처했습니다. 가구는 전부 가상입니다.
- 값은 **캡처 화면에 찍힌 숫자만** 옮겼습니다. 화면에 없는 값은 계산해서 채우지 않고 비워 두었습니다.
- 입력값은 입력표(프로젝트 파일 `issue-drafts/pr03c-hometax-input-sheet.md`)와 칸별 입력 카드(`issue-drafts/pr03c-run-cards.md`)에서 옮겼습니다.
- 캡처 원본은 레포에 넣지 않습니다. 프로젝트 파일 `hometax-2025-runs/`에 있고, 사례 파일의 `capture` 칸이 그 파일 이름입니다.
- 2026-11-17 AJin1068의 요청으로 4건 모두 `confirmed`로 바꿨습니다(`review.scope`). 값 대조는 Claude가 했고(기록표 결정세액 일치, 화면 값끼리 더하고 빼는 식 확인), 사람이 캡처와 한 줄씩 대조한 기록은 없습니다. 그래서 PR 4·5 테스트에서 값이 어긋나면 이 파일부터 의심합니다. 계산 엔진 테스트는 `confirmed`만 씁니다.

### 배분이 갈리는 곳

- **가구 1**: 둘째(5세)를 아내가 받는 B가 A보다 부부 합계 45,000원 적습니다. 기록표 메모로는 의료비 문턱(총급여의 3%) 차이 때문입니다.
- **가구 2**: 시어머니 공제와 의료비를 같은 사람(남편)이 받는 A가 B보다 240,000원 적습니다. B에서는 아내가 낸 시어머니 의료비가 공제되지 않기 때문입니다(아래).

### 가구 2 배분안 B 아내를 실행하지 않은 이유

국세청 「2025년 원천징수의무자를 위한 연말정산 신고안내」(2025.12 발간, 정오표 2026.02.03) 인쇄 p389(PDF 407쪽) 부록 4 「맞벌이 부부 연말정산」 표의 의료비 세액공제 · 배우자 외 부양가족 칸에 "부부 중 부양가족을 기본공제 받는 근로자가 부양가족을 위해 지출한 금액 공제"라고 되어 있습니다. 시어머니 기본공제는 남편이 받으므로, 아내가 낸 시어머니 의료비 400만원은 공제되지 않습니다. 그러면 아내 입력이 배분안 A 아내와 똑같아지고 결과도 같습니다.

홈택스 계산 화면은 사람 한 명씩 계산하므로 누가 부양가족 기본공제를 받았는지 모릅니다. 아내 쪽에 의료비를 넣으면 그대로 공제해 버려 법과 다른 답이 나옵니다. 그래서 실행하지 않았고, `household2-plan-b.json`의 아내 결정세액 713,375원은 **홈택스 결과가 아니라 위 문서 근거로 판단해 배분안 A 아내 실행 결과를 가져온 값**입니다. 그 줄에는 `not_from_this_run: true`와 `basis`(문서 근거)가 붙어 있고, `not_run`에 이유를 적었습니다.

## 파일 형식

3a(`../nts-2025/README.md`) 형식을 따르되, 한 사례에 부부 두 사람이 있어서 `expected` 한 줄마다 `person`을 붙이고, 문서 쪽수 대신 캡처 파일 이름을 적습니다.

```jsonc
{
  "id": "hometax2025-h1-B",
  "status": "draft",                         // draft | confirmed
  "review": {"reviewer": null, "date": null},
  "tax_year": 2025,
  "source": {
    "tool": "홈택스 연말정산 미리보기 > 세액계산 화면 (2025 귀속)",
    "run_date": "2026-11-17", "run_by": "AJin1068",
    "input_sheet": "...", "captures_dir": "...",
    "captures": {"husband": ["h1-B-남편.png", ...], "wife": [...]}
  },
  "kind": "household",
  "groups": ["basic_flow", "dependents", "child", "medical", "education", "card"],
  "household": "h1", "plan": "B",
  "question": "...",
  "allocation": {"첫째(10세) 기본공제·자녀세액공제·교육비": "husband", ...},  // 무엇을 누가 받나
  "inputs": {"family": {...}, "husband": {...}, "wife": {...}},             // 홈택스에 넣은 값, 원 단위 정수
  "expected": [
    {"person": "wife", "stage": "medical_credit", "value": 97500,
     "capture": "h1-B-아내-상세4.png", "screen_label": "특별세액공제 의료비 세액공제액"}
  ],
  "not_run": [],                             // 실행하지 않은 사람과 이유
  "notes": ["..."]
}
```

- `expected`의 `value`는 원 단위 정수(명 수와 세율 %도 정수)입니다. `screen_label`은 화면의 칸 이름입니다.
- `inputs.*.screen_insurance_premium`은 홈택스 "건강보험료 등" 칸에 넣은 값(건강보험 + 고용보험)입니다.
- `refund_or_payment`는 화면의 차감징수세액(소득세)입니다. 기납부세액을 0원으로 넣었기 때문에 결정세액에서 10원 미만을 버린 값이 나옵니다(예: 2,721,875 → 2,721,870).
- 지방소득세는 5그룹 밖이라 옮기지 않았습니다.

## 형식 검사

```bash
python3 eval/cases/hometax-2025/check_cases.py
```

필수 칸, 값 타입, 단계 이름이 위 표에 있는지, `capture`가 `source.captures`에 있는지, 부부 둘 다 `determined_tax`가 있는지 봅니다. 값이 맞는지는 보지 않습니다(사람이 캡처와 대조).

옮긴 뒤 화면 값끼리 더하고 빼서 맞는지(근로소득금액 = 총급여 − 근로소득공제, 결정세액 = 산출세액 − 세액공제계 등)도 한 번 확인했고 모두 맞았습니다. 이것은 옮겨 적기 실수를 찾으려는 확인이고, 화면에 없는 값을 채우는 데는 쓰지 않았습니다.
